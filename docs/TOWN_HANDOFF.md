# 마을 제작 인계
기록: 2026-10-19 Asia/Seoul
저장소: https://github.com/knc219-a11y/grovebound
작성 시 최신 main: f1f5c4f17bfda6fbda56ad0df59b1001bb861f66

## 사용자 결정과 이번 인계 범위
- 다음 대화의 작업은 마을 제작이다. 이번 대화에서는 인계 문서만 작성했으며 마을을 구현하지 않았다.
- 마을의 이름·건물 배치·NPC·구체적인 시설은 아직 사용자가 확정하지 않았다. 아래 첫 구현 범위는 기존 기능을 활용하는 제안이며 확정된 설정으로 취급하지 않는다.
- 다른 저장소의 사이드뷰 ARPG/신의 유해 설정과 혼합하지 않는다. 이 프로젝트는 Grovebound의 드루이드·동물 동료 수집 RPG다.

## 유지할 기준
- 먼저 AGENTS.md, STATUS.md, docs/NEXT_SESSION.md를 읽고 최신 main을 확인한다. 이 문서보다 이후 사용자 지시가 우선한다.
- Godot 4.7 Standard, 모바일 가로화면. 차분하고 선명한 쿼터뷰 도트풍, 기존 석판/청동 UI·한국어 폰트를 이어간다.
- 작은 캐릭터와 넓은 시야를 유지한다. 드루이드 기본72px/일반 멧돼지48px. 건물·길·문·소품을 캐릭터 기준으로 맞춘다. 캐릭터 확대나 줌으로 배경 비율을 해결하지 않는다.
- 기존 전투 맵은 assets/maps/greenwater-beginner-v3.webp, 월드2900×1650/논리 화면1440×810. 마을은 별도 공간으로 만들며 전투 맵을 덮어쓰지 않는다. 마을 맵 크기는 아직 미정이다.
- 블록 퍼즐 제외, 성장·동료 수집 우선. IV 없음. 종/레벨+고정 특성1개+등급별 랜덤 옵션. 포획·표시·저장 시 재추첨 금지.
- 활동 동료4/동행6, 기존 성장·수집 밸런스와 사용자 세이브·도감·즐겨찾기를 보존한다.

## 현재 구현 상태와 연결 지점
- 현재 캠프는 걸어다니는 마을이 아니라 show_camp()의 전체화면 모달이다. 마을 이동·건물 충돌·NPC 상호작용은 아직 없다.
- main.gd: show_camp(), start_stage(), finish(), confirm_return(), resume_game(), navigate_back(), can_act(), _input/_unhandled_input, 저장/로드를 확인한다. camp 문자열에 연결된 육성·귀환·뒤로·메뉴 조건이 많으므로 이름만 바꿔 기능을 깨뜨리지 않는다.
- ui/game_menu.gd: 실제 보유 동료 가방/재료 탭, 영구 발견 도감, 여정 현황, 조작 안내. 보관함·상세·비교·육성은 기존 기능으로 연결돼 있다.
- ui/dropdown_menu.gd + ui/menu_tile.gd: 우측 상단 가로줄3개, 아이콘+짧은 이름. 5열 자동 줄바꿈. 가방/동료/도감/여정/조작, 다음 줄 재료/캠프. 바깥 클릭·재누름·Esc 닫기, 펼침 중 전투 일시정지. 마을에서도 이 메뉴를 유지한다.
- 메뉴 page와 실제 게임 mode는 분리돼 있다. 마을에서 가방/도감을 열고 닫아도 같은 위치로 돌아와야 한다. 현재 resume_game()의 camp 분기는 모달을 다시 여므로 마을 도입 시 재검토한다.
- 마을의 안전한 이동과 전투 행동을 구분한다. can_act()를 무조건 풀어 마을에서 전투/포획/보상이 작동하게 하지 않는다. 전투 중 편성 제한 및 캠프 육성 조건도 보존한다.
- 현재 전투 배경은 단일 이미지로 소품 충돌/길찾기가 없다. 마을 건물은 이동 가능한 길과 충돌·앞뒤 가림을 함께 설계해야 한다.
- 최신 UI 실물: docs/dropdown-menu.png. docs/menu-*.png 및 refined-ui-*.png는 기존 화면 참고. 과거 하단 내비게이션 캡처를 최신 메뉴로 오해하지 않는다.

## 첫 구현 범위 제안
1. 작은 드루이드가 직접 걸을 수 있는 아담한 마을 허브부터 구현한다. 넓은 이동 동선과 판독 가능한 시설 입구를 우선한다. 웅장한 도시나 거대한 계단으로 시작하지 않는다.
2. 입구/중앙 쉼터/동료 관리 지점/사냥터 출구 정도를 먼저 구성한다. 시설 명칭과 형태는 현재 아트에 맞게 제안한다.
3. 동료 관리 지점에서는 기존 편성·성장 화면을, 출구에서는 기존 첫 동료 튜토리얼/스테이지 출발 흐름을 재사용한다. 기존 가방/도감은 공통 메뉴에서 접근한다.
4. 접근 시 짧은 이름과 상호작용 안내를 표시한다. PC F와 모바일 버튼 모두 지원하되 포획·소생 입력과 충돌하지 않게 한다.
5. 마을→튜토리얼/사냥터→귀환→마을, 메뉴 열기/닫기, 로드 후 시작 위치를 검증한다. 건물 안으로 파고들거나 시설 사이에 끼지 않는지 확인한다.
6. 실제 게임 전체 화면으로 건물·캐릭터 비율을 검토하고 필요하면 소품을 줄인다. 시안 이미지만으로 구현 완료라고 하지 않는다.
- 상점·재화 경제·제작·퀘스트·주인공 성장·중복 소비·새 NPC 서사는 이번 최소 마을의 필수 기능으로 가정하지 않는다. 필요하면 별도 제안한다.

- Godot 임포트 및 변경에 맞는 self-test/UI/game_menu/save_repair 검사. 실제 마을 이동·충돌·시설 진입·출발·귀환·메뉴 복귀 검증을 추가한다.
- tools/preview.py를 재사용해 실제 Godot 마을 전체 스크린샷을 제공한다. 이동·전환을 수정하면 실제 GIF와 MP4도 제공한다. 캡처 장면은 사용자 세이브를 읽거나 덮어쓰지 않는다.
- Parse/SCRIPT ERROR와 실제 PASS를 확인한다. 실기기/전체 플레이를 수행하지 않았다면 그 한계를 명시한다.
- 관련 파일만 GitHub에 반영하고 STATUS.md/NEXT_SESSION.md를 갱신한다. 동시에 다른 대화가 같은 파일을 수정하지 않도록 최신 main과 충돌을 확인한다.

현재 전체화면 캠프를 바탕으로, 캐릭터가 직접 걸어다니며 탐험을 준비하는 작은 마을 허브를 만들어줘. 작은 캐릭터와 넓은 시야, 기존의 선명한 쿼터뷰 도트풍을 유지하고 건물·문·길·소품 크기를 캐릭터 기준으로 맞춰줘. 캐릭터 확대나 카메라 줌으로 해결하지 말고 기존 사냥터 배경도 보존해줘.

첫 단계는 마을 이동, 건물 충돌과 앞뒤 가림, 동료 관리 지점, 사냥터 출구, 기존 튜토리얼/탐험 출발 및 귀환 연결에 집중해줘. 편성·육성·가방·도감은 기존 기능을 재사용하고, 우측 상단 햄버거 메뉴의 아이콘+짧은 이름/한 줄5개/자동 줄바꿈을 유지해줘. 메뉴를 닫으면 마을의 같은 위치로 돌아오게 해줘. PC와 모바일 상호작용을 지원해줘.

구체적인 마을 이름이나 NPC·시설 설정은 아직 확정하지 않았으니 기존 분위기에 맞는 작은 구성으로 제안하고 구현해줘. 새 경제·상점·제작·퀘스트·성장 규칙까지 임의로 확장하지 말고 기존 세이브·수집·성장 데이터와 밸런스를 보존해줘.

계획 설명에서 끝내지 말고 실제 Godot 구현·검증까지 진행하고, 실제 게임 스크린샷과 이동/전환 GIF·MP4를 보여줘. 관련 변경을 GitHub에 반영하고 인계 문서도 갱신해줘.
