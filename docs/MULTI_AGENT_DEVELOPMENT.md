# Grovebound 병렬 멀티 에이전트 개발 규칙

이 문서는 여러 작업이 같은 저장소에서 안전하게 진행되기 위한 운영 기준이다. 게임 설정은 `PROJECT_SETTINGS.md`, 구현 상태는 `STATUS.md`, 바로 다음 작업은 `NEXT_SESSION.md`가 우선한다.

## 불변 조건
- 기존 게임 설정, 동료 ID·종·특성·옵션·편성·진화 결과와 사용자 저장을 보존한다.
- Godot 4.7 Standard, 모바일 가로 화면, 작은 캐릭터·넓은 시야와 승인된 도트풍을 유지한다.
- 미정인 심층 콘텐츠, 야생 2·3성 분포, 입장 재화 수치는 사용자 승인 없이 구현하지 않는다.
- 자동 검증, 실제 Godot QA, 사람 난이도와 실기기 검증을 서로 바꾸어 설명하지 않는다.

## 역할과 소유권
| 역할 | 기본 소유 영역 | 책임 |
|---|---|---|
| 통합 리드 | `main.gd`, `main.tscn`, `project.godot`, 저장 스키마, 공통 인계 문서 | 계약 승인, 연결, 전체 회귀, 최종 병합 |
| 전투·성장 | 전투·AI·합성·승급·진화 모듈 | 독립 규칙과 집중 테스트 |
| 캠페인·데이터 | 캠페인/지역/종/보상 데이터 | 해금·배치·보상 규칙과 테스트 |
| UI·UX | `ui/` | 표시 모델과 사용자 명령, UI 회귀 |
| 아트·모션 | `assets/`, 제품용 `animation/` | 승인 비율·팔레트·실제 속도 검토 |
| QA·릴리스 | `tools/`, 검토 장면, 검사 결과 | 독립 재현, 회귀, 증거와 원격 결과 확인 |

통합 리드 전용 파일은 다른 역할이 직접 고치지 않는다. 필요한 변경은 인수인계의 `통합 요청`에 정확한 호출 지점과 기대 동작으로 남긴다. 한 파일과 한 장면은 한 시점에 한 소유자만 가진다.

## 작업 분리 승인 조건
다음 조건을 모두 만족해야 병렬로 실행한다.
1. 기준 main의 전체 SHA가 같다.
2. 입력·출력 계약과 제외 범위가 기록돼 있다.
3. 쓰기 대상 파일이 겹치지 않는다.
4. 저장 또는 공통 API 변경은 선행 계약 PR로 병합됐다.
5. 각 작업에 독립적인 집중 검사가 있다.

하나라도 만족하지 않으면 선행/후속 PR로 순차 처리한다.

## Worktree·브랜치·PR
1. 통합 리드가 최신 `origin/main` SHA와 작업 그래프를 기록한다.
2. 계약 변경이 있으면 `contract/<이름>` PR을 먼저 병합한다.
3. 병합된 같은 SHA에서 작업마다 별도 worktree를 만든다.
4. 브랜치는 `feat/`, `fix/`, `test/`, `art/`, `contract/`, `integrate/` 접두사를 사용한다.
5. 기능·리팩터링·대규모 에셋 변경을 한 PR에 섞지 않는다.
6. 제품 PR은 통합 리드 전용 파일을 건드리지 않는다. 연결은 `integrate/` PR에서 수행한다.
7. 최신 main 반영, 필수 검사와 인계 확인 후 squash merge한다.
8. 원격 병합 SHA와 CI 결과를 확인한 뒤 worktree를 정리한다.

## Godot 충돌 회피
- `main.tscn`과 같은 공통 씬은 통합 리드만 수정한다.
- 새 기능은 독립 `.gd` 또는 하위 씬으로 만들고 부모 연결은 통합 단계에서 수행한다.
- `.tscn` 충돌을 자동 병합하지 않는다. 먼저 병합된 변경 위에 후속 변경을 Godot에서 재적용한다.
- 편집기를 열고 닫아서 생긴 무관한 직렬화, `.uid`, `.import` 변경을 제거한다.
- 검토 장면과 제품 장면을 분리하고 검토·녹화는 사용자 `user://` 저장을 읽거나 쓰지 않는다.
- Autoload, InputMap, 렌더러나 해상도 변경은 독립 계약 PR과 사용자 승인이 필요하다.

## 검증 게이트
### 기능 PR
- Godot import 성공, Parse/SCRIPT ERROR 없음
- 변경 모듈 집중 검사 통과
- 사용자 저장 미사용, 범위 밖 수치 무변경
- 불필요한 장면·에셋 직렬화 변경 없음

### 통합 PR
- 최신 전체 회귀와 `python tools/check_handoff.py` 통과
- 구세이브 로드·저장 왕복·저장 실패 무변경 검사
- 기존 동료와 캠페인 진행 회귀
- 실제 Godot 렌더 검토 1개 이상
- UI·배경은 인게임 스크린샷, 모션은 실제 Godot GIF·MP4
- 미실행 검사와 알려진 경고를 명시
- 원격 CI와 병합 SHA 확인

## 인수인계
각 PR은 `.github/pull_request_template.md` 항목을 채운다. 복잡한 작업은 `docs/handoffs/<작업명>.md`에 기준 SHA, 목표/제외, 소유 파일, 계약 변경, 보존 조건, 검사 결과, 미검증, 저장 영향, 위험, 통합 요청과 후속 작업을 남긴다.

## 첫 파일럿
운영 기반 병합 후 첫 병렬 파일럿은 입장 재화다. 먼저 대상 전투, 일일량, 회복, 비용을 사용자에게 승인받는다. 승인 전에는 `docs/contracts/`의 확장점과 테스트 시나리오만 설계하고 게임 코드·수치·저장을 바꾸지 않는다. 심층 구현은 파일럿과 사람의 일반 후반 피드백 이후 다시 시작한다.
